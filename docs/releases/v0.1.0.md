# AuraPass v0.1.0 — Draft release notes

> Prepared for review as part of the v0.1.0 release preparation. This document does not create a Git tag, package, or GitHub Release.

## Overview

AuraPass is an offline examination-access engineering prototype. This initial source release documents the existing workflow for course-form enrollment, local face matching, exam eligibility decisions, seat assignment, audit records, and Arduino/Proteus co-simulation.

## Included capabilities

- Parse student and course fields from the supported course-form PDF layout.
- Enroll local face samples and create multiple templates using the selected embedding backend.
- Use OpenCV YuNet and SFace by default, with optional DeepFace/FaceNet support and a development-only LBP mode.
- Check course registration, repeat scans, session capacity, and seat placement through the exam policy service.
- Record local attendance decisions and encode `V`, `O`, `C`, and `F` controller commands for the existing loopback UDP/serial bridge.
- Run a deterministic synthetic exam-access demo with fictional student records and no biometric analysis or hardware connection.
- Run unit and integration tests using a fictional course-form fixture and synthetic numeric vectors.

## Getting started

For the no-hardware workflow, use Python 3.10 or later and run the synthetic demo from the repository root:

```powershell
py -3 tools\synthetic_exam_demo.py
```

This demo needs only the Python standard library and uses a temporary SQLite database. For full application installation, downloaded model checksums, and test commands, follow the [README](../../README.md). Continuous integration currently runs on Windows with Python 3.12.

## Scope and limitations

AuraPass is not a production biometric security or attendance product. The release does not claim biometric accuracy, fairness, liveness detection, presentation-attack resistance, controller actuation, electrical safety, or deployment readiness.

Known limitations include:

- Recognition thresholds are prototype values and have not been independently calibrated for a target population.
- Liveness and presentation-attack detection are not implemented.
- SQLite records and biometric templates are not encrypted at rest; operator authentication, consent capture, retention scheduling, and automated deletion are not implemented.
- The PDF parser supports one known course-form text layout.
- Guided right/left/centre capture prompts do not verify head pose.
- The UDP/serial controller path has no authentication, encryption, acknowledgement, or replay protection.
- Proteus co-simulation is not evidence of a fabricated or production-ready gate.

The included synthetic tests and demo use fictional identifiers and injected policy outcomes. They do not process real biometric data and do not validate the recognition models.

## Privacy and licensing

Face images, embeddings, identity records, attendance decisions, and controller activity should be treated as sensitive. Runtime data is excluded from Git, but local database storage is plaintext. Read the [security and privacy notes](../SECURITY_AND_PRIVACY.md) before any real evaluation; define a lawful purpose, consent basis, access controls, retention, and deletion process first.
