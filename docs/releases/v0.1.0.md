# AuraPass v0.1.0

AuraPass v0.1.0 is the first public source release of an offline examination-access engineering prototype. It documents a workflow for course-form enrollment, local face matching, examination eligibility decisions, seat assignment, audit records, and Arduino/Proteus co-simulation.

## Included capabilities

- Parse student and course fields from the supported course-form PDF layout.
- Enroll face samples locally and create multiple templates with the selected embedding backend.
- Use OpenCV YuNet and SFace by default, with optional DeepFace/FaceNet support and a development-only LBP mode.
- Check course registration, repeat scans, session capacity, and seat placement through the exam policy service.
- Record local attendance decisions and encode `V`, `O`, `C`, and `F` controller commands for the existing loopback UDP/serial bridge.
- Run a deterministic synthetic exam-access demo with fictional student records and no biometric analysis or hardware connection.
- Run unit and integration tests using a fictional course-form fixture and synthetic numeric vectors.

## Try the synthetic demo

From the repository root, run the demo with Python 3.10 or later:

```powershell
py -3 tools\synthetic_exam_demo.py
```

The demo uses fictional records, injected synthetic policy outcomes, and a temporary SQLite database. It does not capture or analyze biometric data. It does not require model files, a camera, Arduino, Proteus, or a serial bridge. Printed controller commands are dry-run text and are never transmitted.

## Scope and limitations

AuraPass is an engineering prototype, not a production biometric security or attendance product. This release makes no claim of biometric accuracy, fairness, liveness detection, presentation-attack resistance, controller actuation, electrical safety, or readiness for deployment.

Known limitations include:

- Recognition thresholds are prototype values and have not been independently calibrated for a target population.
- Liveness and presentation-attack detection are not implemented.
- SQLite records and biometric templates are not encrypted at rest; operator authentication, consent capture, retention scheduling, and automated deletion are not implemented.
- The PDF parser supports one known course-form text layout.
- Guided right/left/centre capture prompts do not verify head pose.
- The UDP/serial controller path has no authentication, encryption, acknowledgement, or replay protection.
- Proteus co-simulation is not evidence of a fabricated or production-ready gate.

Synthetic tests and the demo use fictional identifiers and injected policy outcomes. They do not process real biometric data and do not validate recognition models.

## Privacy and licensing

Face images, embeddings, identity records, attendance decisions, and controller activity should be treated as sensitive. Runtime data is excluded from Git, but local database storage is plaintext. Review the [security and privacy notes](https://github.com/Elijahpeters/AuraPass/blob/v0.1.0/docs/SECURITY_AND_PRIVACY.md) before any real evaluation; define a lawful purpose, consent basis, access controls, retention, and deletion process first.
